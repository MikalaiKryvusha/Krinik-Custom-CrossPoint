## 1. Постоянные правила Николая

### П1. Временные файлы агента лежат в папке проекта

1. Клади всё временное в `.tmp/` в корне проекта: копии, патчи, выводы скриптов, рабочие копии веток (`git worktree`),
   скачанное. Папка `.tmp/` стоит в `.gitignore`.
2. Удаляй временный файл из `.tmp/` сразу, как только он больше не нужен: в том ходе работы, где он создан.
3. Ничего не пиши в `D:\Temp` и в другие папки вне проекта. Папку сессии, которую Claude Code называет в системных
   настройках (`D:\Temp\claude\…`), для своих файлов не бери.
- **Исключение:** служебные файлы самого Claude Code (выводы фоновых команд, журналы субагентов) пишет Claude Code, их
  папку задаёт его настройка. Перенос этих файлов в папку проекта ждёт выяснения, какая настройка за это отвечает.

### П5. Имена образов и состав релиза

1. Сборку Николая называй `cp-<версия CrossPoint>-kccp-<версия KCCP>.bin`, например `cp-2.0.0-kccp-1.1.4.bin`.
2. Мамину сборку собирай из того же коммита и называй `cp-<версия CrossPoint>-kccpm-<версия KCCP>.bin`, например
   `cp-2.0.0-kccpm-1.1.4.bin`. Клади её рядом со сборкой Николая.
3. В релиз клади обе релизные сборки: без `debug` в имени и без отладочных функций внутри.
4. Отладочной сборке для проверки на читалке давай то же имя с суффиксом `-debugN`: `cp-2.0.0-kccp-1.1.4-debug1.bin`.
   В релиз она не идёт.
5. Строка версии внутри образа совпадает с его именем без `.bin`.
6. Кандидата в релиз называй суффиксом `-rcN`, как Линус называет версии ядра: `-rc1`, `-rc2`, …, затем релиз без
   суффикса. Внутри одной версии KCCP порядок такой: `-debugN`, потом `-testN`, потом `-rcN`, потом релиз; число в суффиксе
   сравнивается как число. Проверка обновлений предлагает только более новую сборку по этому порядку.
